环境自检

WSL 报错、启动隐患、凭据体检
WSL 报错

Antigravity 用绝对路径 C:\Windows\System32\wsl.exe 探测 WSL 分发版， 没装 WSL 就刷 wsl --list --verbose failed。 功能完全不受影响，只是日志难看。PATH 劫持无效（实测），改 SystemRoot 会让它起不来。

底层机制

账号到底存在哪、切换时改了哪些字节
  1. 身份本体 = 一条 Windows 凭据
    TargetName = "gemini:antigravity"，blob 是 UTF-8 JSON： {"token":{"access_token","token_type","refresh_token","expiry"},"auth_method":"consumer","writer_id":"…"}
    access_token 约 1 小时过期，refresh_token 长期有效，由 language server 自己续期后写回同一条。
  2. 界面上显示的邮箱 = Hub 本地标记
    %APPDATA%\Antigravity\app_storage.json 的 agy.onboarding.lastLoginUsername / lastLoginIsGcpTos， 外加 credential-user-scope（udc…）。 只换 token 不换这两个字段，界面就会继续显示上一个邮箱。
  3. 切换动作
    写入目标 token → 覆盖邮箱标记与 scope →（可选）清掉 Hub 内嵌浏览器的会话缓存 → 重启 Antigravity.exe，它拉起的 language_server.exe 启动时重新 CredRead。
  4. 为什么不能离线续 token
    LS 内置的三个 client_id 都是 Desktop 类型，刷新必须带 client_secret； 实测该 secret 不落盘、不进环境变量，二进制里只有残片。 所以本工具不伪造刷新：access_token 过期后，切过去让 Antigravity 自己续/重登即可。
  5. 额度数据从哪来
    language server 自己起了一个本地 HTTP 服务 （POST http://127.0.0.1:<httpPort>/exa.language_server_pb.LanguageServerService/…， 鉴权头 X-Codeium-Csrf-Token，端口和 csrf 在 ~/.gemini/antigravity/daemon/hub_<port>.json）。 额度走的 RetrieveUserQuotaSummary、账号信息走的 GetUserStatus， 都是 LS 拿进程内的新鲜 token 去问 Google 后原样转回来的——服务端权威值，不用自己维护 token。
  6. 为什么不能自己拿 token 直连后端
    实测：新建的 token 直连 cloudcode-pa 的额度接口会返回 403 You do not have a valid license of this product， 因为 LS 调用时会附带额外的授权头。所以走本地 API 而不是直连。
  7. 登出 / 再登录
    「登出」删凭据 + 通知 LS AuthLogout + 重启 Hub； 「登录 / 切换 Google 账号」调 LS 的 Login， 已登录时它直接返回 hasValidAuth=true 不弹窗，登出后才会给出 auth_url。
  8. 安全
    账号库 accounts.dat 用 DPAPI（CurrentUser）整体加密，换机器/换用户都解不开； 每次写盘滚动备份，保留最近 10 份。
